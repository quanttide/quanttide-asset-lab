# 改造路线

本项目的改造目标是把重心从 Skill 换到 CLI：CLI 成为正式发布、稳定维护的产品，一个或多个 Skill 作为薄调用方去使用它，而不是像现在这样由 Skill 主导、CLI 寄居在 Skill 目录内。

---

## 现状

当前结构是 Skill 优先的产物。`engine.py` 是全部业务实现，却以脚本身份放在技能目录里，入口写死为 `python3 src/engine.py`，规格文件靠 `Path(__file__).parents[1]` 相对定位。文档面向「读 Skill 的 AI」而不是「用 CLI 的人」，`docs/index.md` 讲的是执行步骤与完成判断，不是安装与命令参考。

这种方式限制了复用。CLI 的能力被绑定在单一 Skill 的生命周期上，想再加一个 Skill 就得复制一份脚本；路径假设让代码无法被安装进站点-packages；没有版本化的命令接口，调用方只能依赖文件布局这种内部细节。

## 目标

CLI 是唯一的能力提供方，拥有稳定的命令接口、明确的版本与退出码，可安装可分发。Skill 只做三件事：理解用户意图、生成请求 YAML、调用 CLI 并转述结果。规则正文留在锁定来源的规格文件里，由 CLI 统一校验，Skill 不复制规则。

| 维度 | 现状 | 目标 |
|:--|:--|:--|
| 主体 | Skill 主导，CLI 寄居其内 | CLI 为主，Skill 为调用方 |
| 入口 | `python3 src/engine.py`，依赖文件布局 | 控制台命令，与安装位置无关 |
| 规则载体 | 散落在 Skill 文档与脚本注释 | 集中于规格文件，CLI 统一校验 |
| 扩展 | 新增 Skill 需复制脚本 | 新增 Skill 只写调用与意图理解 |
| 分发 | 复制目录即可用 | `pip install` 后可用 |

## 阶段

### 一、清理重组残留

三处残留已确认，都是改字面量：`validate_outputs.py` 的 `required` 改为新布局，`docs/index.md` 的 `scripts/` 与 `references/` 引用改到 `src/` 与 `docs/`，`specification.yaml` 的 `runtime.entrypoint` 改为新入口。

这一步只消除不一致，不改变行为。

### 二、建立项目骨架

补 `pyproject.toml`，确定包名与控制台命令名；把 `src/` 下的脚本变成包，补 `__init__.py` 与 `__main__.py`；补 `.gitignore` 排除 `__pycache__`。

这里有一个必须解决的技术点：`SPEC` 依赖 `parents[1]` 定位 `assets/specification.yaml`，一旦安装进站点-packages，这个相对路径就断了。规格文件需要改为随包分发的资源，用 `importlib.resources` 读取，或者在 `pyproject.toml` 里声明为 package data 并调整定位方式。`engine_sha256` 同样依赖引擎文件路径，需要一并确认在安装形态下仍能取到稳定内容。

### 三、把 CLI 做成稳定接口

给四个子命令补 `--version`，约定退出码语义（`0` 通过、`1` 校验失败或执行暂停），错误信息统一走 stderr。请求配置的读取从隐含的相对路径改为显式参数或环境变量，去掉对工作目录的依赖。

同时补测试。现有代码对失败路径的处理是重点：计划指纹失配、确认记录不完整、推送结果不确定时先对账，这些分支应当被覆盖。测试沿用真实本地 Git 仓库而非 mock，与原始项目 17 个测试文件的做法一致。

### 四、主从反转

CLI 稳定之后再做这一步，顺序不能颠倒，否则 Skill 会去调用一个仍在变动的接口。

拆分的判据是：凡是「理解意图、调查先例、选择场景、把自然语言写成规格允许的配置」留在 Skill；凡是「校验、计划、执行、验证」全部收进 CLI。Skill 的 `SKILL.md` 缩减为调用说明，规则正文不再进 Skill。

按需要增加第二个、第三个 Skill，例如只做只读调查的 Skill，或者只负责发布与更名的 Skill。它们共享同一个 CLI，不各自持有脚本副本。新增 Skill 的成本应当只是写一份意图理解与调用示例。

### 五、发布与文档

补 README 的安装章节与命令参考，`docs/index.md` 改写为面向使用者而非面向读 Skill 的 AI。确定版本策略后发布首个版本。

## 分阶段验收

第一阶段以 `validate_outputs.py` 返回 0 为准。第二、三阶段以安装后在任意目录执行控制台命令能跑通四个子命令为准。第四阶段以一个不含任何脚本的新 Skill 能完成端到端流程为准。第五阶段以新人按 README 独立跑通一次 local 模式为准。
